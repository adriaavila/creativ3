# allok: image-first redesign

28 October 2026. Prototype only. No production changes.

## Positioning proposal

**allok is an AI-native design and software studio for businesses with real operational work to solve.**

Customer-facing copy: «Diseñamos productos, conectamos tu operación y ponemos la IA a trabajar.» Three clear ways in: AI agents, custom software and product design. A direct conversation is the conversion action.

The studio positioning does not change Vocero's product or its pricing. It should provide a clear path to the existing WhatsApp product. The current company objective is paying product customers; visual attention alone is not the success measure.

## Visual decision

- **A / Open Systems, recommended:** dark opening, large concise typography, source project screenshots. Closest to the existing commercial design rules.
- **B / Proof First:** light editorial layout, product gallery and narrow service column. A deliberate exploration of the portfolio voice on the commercial homepage.
- **C / Blue Studio:** blue typographic poster, one project window. A deliberate departure from the restrained color rule, requiring Adrian's taste decision.

Images are generated hero concepts. They are not deployed site screenshots, proof of customer results or approved brand changes. Original project captures are used in the interactive prototype. The generated appointment screen in A is illustrative.

There are conflicting prices in older marketing documents and current source. No price is proposed or changed here. The working agreement also records an unresolved change of WhatsApp sales number. The prototype uses the verified public email, hi@allok.fun, instead of the old WhatsApp number.

## Ranking: proposed implementation after visual selection

1. **Homepage:** name the service, buyer and market in visible text. Suggested title: «allok | Agentes de IA, software a medida y diseño de producto». Keep semantic HTML text separate from imagery. The expressive headline can coexist with precise descriptions.
2. **Services:** start with the existing `/agente-whatsapp` and `/vocero` routes; sharpen their distinct product-versus-integration intent. Add a custom software page only when it can explain a distinct offer. Avoid duplicate thin service pages.
3. **Cases:** use `/casos/<client>` for first-hand problem → system → evidence. Show real interfaces with useful captions, actual implementation details and only measured results. Do not label prototype screenshots as production outcomes.
4. **Founder and field notes:** make authorship and experience clear; link original writing and project decisions. Useful work samples matter more than generic AI articles.
5. **Technical release:** reconcile the deployed homepage with the intended source; check crawlable links, canonicals, sitemap, robots, responsive images, descriptive alt text, performance and accurate Organization structured data that matches visible facts.
6. **Measurement:** establish the current Search Console baseline before launch. Track relevant service queries, qualified project conversations and product activation. Ranking and AI citations are not guaranteed.

Google says [AI search features use the same SEO foundations](https://developers.google.com/search/docs/appearance/ai-features): the page must be indexed and eligible for snippets, and important content should be available as text. There is no special schema required for AI Overviews or AI Mode.

Use [first-hand, people-first expertise](https://developers.google.com/search/docs/fundamentals/creating-helpful-content), [clear titles, descriptions, links and image context](https://developers.google.com/search/docs/fundamentals/seo-starter-guide), and [accurate Organization data](https://developers.google.com/search/docs/appearance/structured-data/organization). Google's [AI optimization guidance](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) does not require llms.txt or special AI markup.
